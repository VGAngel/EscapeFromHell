## 1. Огляд гри

**Escape from Hell** — одиночний 2D платформер де гравець керує колишнім священиком Данилом, який спускається крізь 10 кіл пекла щоб врятувати 100 душ що потрапили туди помилково.

### Ключові особливості
- 100 основних + 18 бічних рівнів в 10 колах пекла (118 загалом)
- 100 іменних душ з унікальними історіями + 20 прихованих
- Уникання ворогів замість бою (посох лише відштовхує)
- Система гріху що впливає на кінцівку
- 6 різних кінцівок залежно від дій гравця
- Гібридна генерація рівнів (статичні + процедурні)
- Адаптивна музика з шарами
- Android з банерною рекламою та опцією "Без реклами"

## 2. Історія та персонаж

### Данило — колишній священик
Колишній священик що втратив віру. Помер і потрапив між небом і пеклом. Бог дає йому завдання: врятувати 100 душ що опинились у пеклі через бюрократичну помилку.

Щоб вижити в пеклі Данило отримує частину демонічної сили — це дає можливість переносити душі та використовувати посох як зброю, але кожне використання темної сили збільшує гріх.

### Пролог
8 сцен діалогу між Данилом і Богом. Не можна пропустити (лише перший запуск). Пояснює:
- Чому Данило тут
- Що таке 100 душ
- Навіщо потрібен посох з демонічною силою
- Що станеться якщо знайде всіх

### Повідомлення Бога
Бог спілкується з Данилом через Хаб Раю перед ключовими рівнями (1, 2, 5, 10, 20, 25, 30, 40, 50, 51, 60, 70, 75, 80, 81, 90, 91, 95, 99, 100) та при особливих подіях (прийнята угода з демоном, гріх > 70%, остання душа).

**Налаштування:** `hub_config.json` → `god_messages`

### Кінцівки (6 варіантів)
Визначаються комбінацією кількості знайдених душ і рівня гріху в кінці гри:

| Кінцівка | Умова |
|----------|-------|
| **Прощення** (Saint) | 100 душ + гріх < 20% |
| **Другий шанс** (Redeemed) | 100 душ + гріх 20–50% |
| **Між світами** (Bound) | 100 душ + гріх 51–80% |
| **Новий Демон** (Fallen) | 100 душ + гріх > 80% |
| **Угода** (Traitor) | < 100 душ + прийняв угоду з демоном |
| **Третій шлях** (Rebel) | Особлива умова — прихована |

**Налаштування:** `localization/uk.json` та `en.json` → `endings`

## 3. Управління

**Платформа:** Android (портретна орієнтація, 1080×1920, 9:16)  
**Скрипт:** `scripts/ui/MobileControls.gd`

### Схема мобільного управління

Екранні кнопки розташовані у нижній частині екрану, над рядком HUD. Позиції автоматично коригуються під SafeArea (банер реклами).

```
┌────────────────────────────────────────┐  ← SafeArea top
│  ♥♥♥    Коло 1•Рівень 1   👻 0/100   ⏸│  ← HUD top row
│                                        │
│              ІГРОВА ЗОНА               │
│                                        │
│  [←] [→]             [⚔] [↑]         │  ← кнопки управління
│  ──────────── ──── ──────────────────  │  ← HUD bottom row
│  ████████████████████████████████████  │  ← sin bar
│  ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  │  ← AdMob banner
└────────────────────────────────────────┘
```

### Кнопки

| Кнопка | Іконка | Розмір | Позиція | Action |
|--------|--------|--------|---------|--------|
| Вліво | ← | 90×90 | нижній лівий кут | `move_left` |
| Вправо | → | 90×90 | поруч з ← | `move_right` |
| Стрибок | ↑ | 120×120 | нижній правий кут | `jump` |
| Посох | ⚔ | 90×90 | лівіше від стрибка | `action` |
| Молитва | 🙏 | 90×90 | контекстна (лише біля вівтаря) | `pray` |
| Пауза | ⏸ | 44×44 | верхній правий кут (HUD) | `ui_cancel` |
| Огляд вниз | ↓ | клавіатура: ↓ або S | — | `look_down` |

### Поведінка кнопок

- **← / →** — утримання = безперервний рух; відпустив = гальмування
- **↑ (Стрибок)** — утримання = вищий стрибок (variable jump); відпустив раніше = нижчий
- **⚔ (Посох)** — одиночне натискання; cooldown 4.5 сек; недоступний під час несіння душі
- **🙏 (Молитва)** — з'являється лише коли гравець в зоні вівтаря; утримання = здача душі

### Взаємодія з вівтарем

| Подія | Тригер |
|-------|--------|
| Підняти душу | автоматично при торканні |
| Прив'язати respawn (без душі) | [E] або 🙏 в зоні вівтаря → промпт "Прив'язати" |
| Доставити душу (з душею) | [E] або 🙏 → анімація + попап + зарахування |
| Відмовитись від душі | — (немає жесту, навмисно) |

### Технічна реалізація

Кнопки емулюють справжні `InputEventAction` через `Input.parse_input_event()`. Це дозволяє `Player.gd` використовувати звичайне polling API (`is_action_pressed`, `is_action_just_pressed`) без змін.

**Input actions** (визначені в `project.godot`):

| Action | Клавіатура (тест/ПК) |
|--------|---------------------|
| `move_left` | ← Arrow |
| `move_right` | → Arrow |
| `jump` | Space |
| `action` | Z |
| `pray` | Ctrl |
| `look_down` | ↓ Arrow або S |
| `interact` | E |
| `ui_cancel` | Escape |

### Камера look-down

Гравець може **затиснути ↓ (або S) на 0.3 с** стоячи на платформі — камера
плавно зміщується на 220 px вниз. Дозволяє "розвідати" що знизу перш ніж
стрибати у шахту наосліп. Реалізація:
[`scripts/managers/LevelCamera.gd`](../scripts/managers/LevelCamera.gd) →
константи `LOOK_DOWN_OFFSET`, `LOOK_DOWN_HOLD_DELAY`. Активується тільки коли
гравець на землі та не натискає `move_left/move_right` (зарезервовано для
майбутнього fast-fall).

### Налаштування кнопок

У `MobileControls.gd` — константи для швидкого коригування:

| Константа | Значення | Опис |
|-----------|----------|------|
| `BTN_ALPHA` | 0.55 | Прозорість кнопок у спокої |
| `BTN_ALPHA_PRESSED` | 0.75 | Прозорість при натисканні |
| `SIZE_LARGE` | 190×190 | Кнопка стрибка / руху |
| `SIZE_MEDIUM` | 150×150 | Кнопка посоха / pickup / pray |
| `GAP` | 18 px | Відстань між кнопками правого кластера |
| `GAP_MOVE` | 36 px | Відстань між ← і → |
| `MARGIN_SIDE` | 32 px | Відступ від краю екрану |
| `MARGIN_BOTTOM` | 24 px | Відступ знизу |

### Користувацька кастомізація мобільних кнопок (C5)

Гравець може **рухати кожну кнопку drag-and-drop** і **масштабувати
загалом** через Settings → Keys → "📱 Мобільні кнопки":

- **Розмір slider 60-140%** — `MobileControls.set_size_scale(scale)`
  ресайзить усі кнопки + corner radii + font в реальному часі.
- **"✋ Редагувати позиції кнопок"** — закриває Settings, MobileControls
  входить у edit-mode (золоті borders), показує floating "✓ Готово"
  overlay поверх гри. У цьому режимі кнопки не запускають input — лише
  переміщуються пальцем. Натиск "Готово" → save + вихід.
- **"↺ Скинути позиції"** — повертає всі offsets + scale до 1.0.
- **Persistence:** `SaveManager.data.mobile_layout = { size_scale: float,
  offsets: { action: {x, y} } }`. Auto-`_flush()` при save щоб crash
  mid-game не втрачав. Vector2 серіалізується як `{x, y}` дикт для
  JSON-сумісності.
- **Offset як delta від default** — при drag-commit обчислюється
  `dropped_pos − default_pos` (а не absolute). Safe-area / scale зміни
  зміщують кнопку коректно.

### Haptic feedback (mobile)

[HapticManager](../scripts/managers/HapticManager.gd) (autoload)
обгортає `Input.vibrate_handheld(duration_ms, amplitude)`. На desktop
автоматично no-op (`OS.has_feature("mobile" / "android")` check).

| Подія | Тривалість | Амплітуда | Тригер |
|-------|------------|-----------|--------|
| `hit` | 80 ms | 0.55 | `Player._take_damage` |
| `jump` | 25 ms | 0.20 | `Player._handle_jump` (звичайний + double) |
| `pickup` | 55 ms | 0.45 | `Player._finish_pickup` |
| `death` | 220 ms | 0.85 | `Player._die` |
| `deliver` | 70 ms | 0.40 | `Player.deliver_soul` |
| `boss_stun` | 3 × 40 ms | 0.55 | `BossLevel._on_boss_stunned` |

**Toggle:** Settings → Sound → "Вібрація (mobile)". Default `true`.
Зберігається в `settings.json` як `haptics: bool`. Jump спеціально
найкоротший і найм'якший — fires часто, не повинен втомлювати.

## 4. Механіки гравця

**Скрипт:** `scripts/Player.gd`  
**Конфіг:** `player_mechanics_config.json`

### Розміри гравця

| Параметр | Значення |
|----------|---------|
| Ширина | 80 px |
| Висота | 100 px |

### Рух
| Параметр | Значення |
|----------|---------|
| Швидкість ходьби | 180 px/s |
| Прискорення (земля) | 800 |
| Гальмування | 1200 |
| Прискорення (повітря) | 500 |
| Гравітація | 900 px/s² |
| Сила стрибка | 600 px/s |
| Максимальна висота стрибка | 200 px (h = v² / 2g) |
| Максимальна швидкість падіння | 600 px/s |
| Coyote time | 0.12 сек |
| Jump buffer | 0.10 сек |

**Coyote time** — гравець може стрибнути ще 0.12 сек після того як зійшов з платформи.  
**Jump buffer** — якщо натиснути стрибок за 0.10 сек до приземлення — стрибок зарахується.

### Variable Jump
Утримуй кнопку стрибка → стрибок вищий (до 0.25 сек утримання).  
Відпустив раніше → стрибок обрізається до мінімальної висоти.

### Посох
Данило використовує посох як захист — він **не вбиває** ворогів, лише відштовхує.

| Параметр | Базово | З апгрейдом |
|----------|--------|-------------|
| Радіус удару | 80 px | +40 px |
| Відстань відльоту ворога | 180 px | — |
| Оглушення ворога | 2.5 сек | — |
| Cooldown | 4.5 сек | 3.0 сек |
| Гріх за удар | +2% | 0% (Чиста Молитва) |

**Обмеження:** посох недоступний коли гравець несе душу (обидві руки зайняті).

### Подвійний стрибок (апгрейд)
Без апгрейду недоступно. З апгрейдом **Легкість Духу** — натиснути стрибок повторно у повітрі → персонаж робить ще один стрибок. Скидається при торканні землі.

### HP та пошкодження
- Базово: 3 HP (серця в HUD)
- Максимум з апгрейдами: 6 HP
- Після удару: 1.2 сек невразливості (блимання спрайту)

#### Пошкодження від падіння
Шкала прив'язана до `MAX_JUMP_HEIGHT = 200 px` (висота одного повного стрибка),
тож при зміні фізики гравця всі пороги перераховуються автоматично.

| Висота падіння | У стрибках | Шкода |
|---|---|---|
| < 300 px | < 1.5 | — |
| 300 – 500 px | 1.5 – 2.5 | −1 HP |
| 500 – 800 px | 2.5 – 4 | −2 HP |
| > 800 px | > 4 | смерть |

Апгрейд **Soft Landing** множить усі пороги на ×1.5 (смерть починається з 1200 px).

Реалізація: `FALL_DAMAGE_TIERS` у [scripts/Player.gd](scripts/Player.gd), функція `_check_fall_damage()`.

## 4. Система гріху

Гріх (0–100%) — центральна механіка що визначає кінцівку гри.

### Джерела гріху

| Подія | Зміна |
|-------|-------|
| Удар посохом | +1% |
| Торкнувся міміка | +10% |
| Прийнята угода з демоном | +20% (+10% з апгрейдом) |
| Смерть | +5% |
| Екзорцизм міміка | −3% |
| Завершення рівня (апгрейд Cleansing) | −5% |
| Прихована душа H19 (sin_freeze) | заморожує на 3 рівні |

### Візуальне відображення
Шкала гріху знизу екрана (HUD). Колір змінюється:
- 0–29%: білий
- 30–59%: помаранчевий
- 60–84%: червоний
- 85–100%: темно-червоний

### Sin-source toast

При кожній зміні гріху HUD показує **transient pop** у нижньому
лівому куті з причиною та значенням:

```
+1% гріх  ⚔ Посох
+5% гріх  💀 Смерть
−5% гріх  ✨ Очищення   (зелений варіант)
```

| Cause | Іконка | Label | Тригер |
|-------|--------|-------|--------|
| `staff` | ⚔ | Посох | удар посохом (якщо нема `staff_purity`) |
| `death` | 💀 | Смерть | `GameManager.trigger_death` |
| `extra_attempt` | 🩸 | Зайва спроба | перевищення death-limit |
| `sin_platform` | 🟥 | Гріховна платформа | стояння на SinPlatform |
| `sin_aura` | 🔥 | Аура Люцифера | boss_10 фаза 2 |
| `demon_deal` | 👹 | Угода з демоном | прийнята угода |
| `corrupt_soul` | 👻 | Зламана душа | (зарезервовано — Soul-affinity S5) |
| `cleansing` | ✨ | Очищення | апгрейд cleansing на завершенні рівня |
| `confession` | 🙏 | Сповідь | (зарезервовано — Confessional booth S7) |

**Throttle:** per-cause cooldown 4с + accumulator. Якщо джерело тригериться
кожен frame (sin_platform 2%/сек), пропущена сума доплачується наступним
toast'ом (наприклад "+6% гріх 🟥 Гріховна платформа" замість 60-ти
крихт). Стек capped на 3 toasts; найстаріший FIFO.

**Стиль:** червоний backdrop + crimson border для +sin, зелений для −sin.
Label 22 px з outline 4 px. Fade-in 0.15 → hold 1.2 → fade-out 0.35с.

**Архітектура:** `GameManager.add_sin(amount, cause)` /
`reduce_sin(amount, cause)` емітять signal `sin_added(amount, cause)`.
HUD підписаний у `_ready()` → `_on_sin_added` → `_spawn_sin_toast`.
Усі call-сайти sin-зміни передають свою cause-строку.

### Вплив на платформи
- **Faith платформа** — стає непрохідною якщо гріх ≥ 50%
- **Sin платформа** — стоячи на ній гріх +2%/сек

**Налаштування:** `hud_config.json` → `sin_bar.colors`

### Whispers (нарративні репліки)

При перетині порогів **30 / 60 / 85%** — над екраном з'являється коротка
репліка від Бога/демона. Логіка: 1 раз на поріг на рівень (не повторюється
доки гравець не пройде наступний рівень або респавн).

**Multi-tier resolution:** при стрибку через декілька порогів за один
delta (наприклад demon-deal 25%→90%) спрацьовує **тільки найвищий**
перетнутий — не спамить усі три.

**Контент:** [whispers_config.json](../whispers_config.json), 4 фрази на
кожен з 3-х tier'ів (`tier_30` / `tier_60` / `tier_85`). Фраза вибирається
рандомно. Легко доповнюється без зміни коду.

**UI:** окрема CanvasLayer (layer 12 — над HUD), `PanelContainer` з

## 5. Механіки душ

**Конфіг:** `soul_mechanics_config.json`

> Розмір soul-спрайту: **70×70 px** (діаметр зони підбору = 70 px, скрипт `Soul.gd`).

### Загальне правило
**Всі душі (крім міміків) треба донести до вівтаря.** Підібрав → несеш → повернувся до вівтаря → натиснув [E]. Без штрафу швидкості — напруга від переслідувачів.

**Послідовність доставки душі:**
1. Підібрав душу → показується панель з ім'ям та епітафією (візуальна ідентифікація)
2. Несеш душу назад до вівтаря (промпт змінюється на "Доставити душу")
3. [E] → анімація світлового стовпа з вівтаря (біло-золотий промінь)
4. Над екраном з'являється напис **"✦ [Ім'я] ✦"** на CanvasLayer
   (layer 11, над HUD) — Label 56 px з товстим outline. Світ
   **замерзає** (`get_tree().paused = true`) на ~1.6с щоб вороги не
   поранили гравця під час celebration. Pre-pause snapshot щоб не
   зачепити PauseScreen якщо він уже відкритий.
5. Душа зараховується в колекцію

**Смерть з душею:** душа падає на місці смерті гравця і чекає наступного забігу.

### Ємність перенесення (Soul Echo)

За замовчуванням гравець несе **1 душу одночасно**. Апгрейд `soul_echo`
("Подвійна Ноша", coст 9 Світла, категорія Душа) піднімає ємність до **2**.

| Стан | Без `soul_echo` | З `soul_echo` |
|------|----------------|---------------|
| Підбір другої душі | блокується | додається у слот |
| Доставка на вівтар | 1 душа за тап | усі душі за один тап |
| Смерть | 1 душа respawn'ить на місці | кожна respawn'ить окремо |

HUD показує індикатор `✋ N/M` лише коли ємність > 1 (без апгрейду — не плутає
гравця "0/1").

**API:** `Player.soul_capacity()`, `Player.is_full()`, `Player.is_carrying()`
+ signal `carry_changed(carried, capacity)`. `carried_soul_ids: Array[String]`
зберігає всі активні душі.

Візуально: душа з'являється над головою гравця, гравець злегка світиться.

### Тип 1 — Невинна душа (Innocent)
- Підібрав торкнувшись → одразу несеш
- Охорона залежить від кола:

| Кола | Охорона |
|------|---------|
| 1–2 | Без охорони або далекий патруль |
| 3–5 | Один ворог впритул |
| 6–8 | Два вороги + пастка |
| 9–10 | Замок — треба активувати механізм |

### Тип 2 — Спляча душа (Sleeping)
1. Підійшов (80 px) → показується іконка + підказка 1.5 сек
2. Стартує рандомна міні-гра з пулу кола
3. Виконав → починаєш нести до виходу
4. Провалив → 20 сек затримки, без штрафу гріху

**Пул міні-ігор по колах:**

| Кола | Доступні типи |
|------|--------------|
| 1–3 | Тиша, Ритм |
| 4–6 | Тиша, Ритм, Вогні |
| 7–8 | Ритм, Вогні, Луна |
| 9–10 | Ритм, Луна, Молитва |

**Міні-ігри:**

| Тип | Іконка | Дія |
|-----|--------|-----|
| Тиша | 🤫 | Стій нерухомо 4 сек |
| Ритм | ♪ | Натискай у такт пульсу (3–5 ударів) |
| Вогні | 🕯 | Збери 3 іскри за 10 сек |
| Луна | 👂 | Послухай патерн → повтори натисканням |
| Молитва | 🙏 | Утримуй кнопку 3 сек (гріх не росте під час утримання) |

### Тип 3 — Душа-пастка / Мімік (Mimic)
Виглядає як звичайна душа, але має візуальні підказки:

| Ознака | Справжня душа | Мімік |
|--------|--------------|-------|
| Пульс | Рівний | Нерегулярний, смикається |
| Тінь | Правильна | Вказує не в той бік |
| Колір | Тепло-білий | Злегка фіолетовий |
| Звук | Тихе сопрано | Легкий дисонанс |

**Варіанти взаємодії:**
- **Утримати кнопку 2 сек поруч** → екзорцизм → мімік розвіюється → гріх −3%, +10 Світла
- **Торкнутись** → гріх +10%, з'являється ворог на 15 сек

Апгрейд **Розпізнавання** підсвічує міміків червоним.

### Система переслідування при підборі душі
Підбір душі видає звук (радіус 200 px). Вороги в радіусі входять в стан ALERT.

| Кола | Час погоні | Швидкість | Макс. переслідувачів |
|------|-----------|-----------|----------------------|
| 1–2 | 4 сек | ×1.1 | 1 |
| 3–4 | 6 сек | ×1.2 | 1 |
| 5–6 | 8 сек | ×1.3 | 2 |
| 7–8 | 10 сек | ×1.4 | 2 |
| 9–10 | 14 сек | ×1.5 | 3 |

Якщо в радіусі більше ворогів ніж ліміт — гоняться найближчі. Решта продовжує патруль.

### Прихована душа
20 прихованих душ (H1–H20) розкидані по всій грі. Видно в сітці колекції завжди (зі знаком ✦ і `?`). Дають унікальні нагороди:
- `sin_freeze_3_levels` — заморозити гріх на 3 рівні
- `reveal_nearby_soul` — підсвітити одну сусідню душу
- `unlock_secret_ending` — розблокувати прихований фінал
- та інші

**Налаштування:**
- Типи та міні-ігри: `soul_mechanics_config.json`
- Список душ та прихованих: `souls_collection.json`
- Тексти імен та епітафій: `localization/uk.json` → `souls`

## 6. Вороги та AI

**Скрипт:** `scripts/enemies/BaseEnemy.gd`  
**Конфіг статів:** `enemies_config.json`  
**Спрайти:** `enemy_sprite_map.json`

### Стейт-машина

```
PATROL → ALERT → CHASE → GIVE_UP → PATROL
							  ↑
						  STUNNED
```

| Стан | Поведінка |
|------|-----------|
| **PATROL** | Ходить між точками, розвертається на стінах та краях |
| **ALERT** | Зупиняється, `!` над головою, 1 сек паузи |
| **CHASE** | Гониться до 6с (`chase_duration`), запам'ятовує позицію гравця |
| **GIVE_UP** | `?` над головою, йде до останньої відомої позиції 2.5с |
| **STUNNED** | Від посоха — відлітає, відновлюється через 4с (default) |

### Виявлення гравця (`_can_see_player`)

Перевірки виконуються по черзі — false на будь-якій → ворог не бачить:
1. **Soul Shield** — апгрейд: 3 сек після підбору душі ворог не реагує
2. **Vertical sight clamp** — `|player.y - enemy.y| > max_vertical_sight`
   (default 100 px) → ні. Гравець на іншому ряду шахти невидимий.
3. **Detection range** — distance ≤ `detection_range` (default 200 px,
   override per enemy в `enemies_config.json`)

### Просторовий звук
Дихання ворога чути з відстані 300 px — ще до того як гравець його бачить. Гравець може орієнтуватись на звук.

### Soul Shield взаємодія
Якщо активний апгрейд **Soul Shield** — 3 сек після підбору душі вороги не реагують на гравця.

### Візуальний фідбек удару посохом
- **Іскри** (`ParticleEffects.spawn("staff_impact", ...)`) — короткий burst
  18 жовтих частинок на місці потрапляння (`Player._apply_staff_hit`)
- **Білий flash** (`BaseEnemy.flash_white(0.08)`) — modulate тимчасово
  виставляється на over-bright (2.5×), tween назад до збереженого оригіналу
- **Time-scale dip** — `Engine.time_scale = 0` на 0.08 с при першому хіті

## 8. Рівні та генерація

**Конфіги:** `levels_config.json`, `level_generation_config.json`

### Структура гри
10 Кіл × 10 рівнів = **100 основних рівнів** + **18 бічних** (кола 1–9, по 2 void на коло) = **118 рівнів**.

**Нумерація бічних рівнів:** `branch_id = parent_id + 100`  
Бічні рівні завжди мають `id > 100`. Батьківський рівень: `branch_id - 100`.
**Усі бічні рівні — `void`** (необов'язкові, з ліворуч).

### Типи рівнів — детальна механіка

---

#### `vertical` — Вертикальний

**Суть:** рівень-хребет кола. Гравець входить через вівтар на верху, спускається вниз, збирає іменну душу і повертається до вівтаря щоб доставити її до раю. Після доставки відкривається прохід до наступного рівня.

**Вівтар:**
- Знаходиться на **верху** кожного vertical рівня — це одночасно і точка входу, і точка доставки душі.
- Гравець **входить** у рівень через вівтар (спускається вниз від нього).
- Щоб завершити рівень — треба **повернутись** до вівтаря з душею і натиснути [E].
- Після доставки: анімація "душа летить до неба", прохід донизу до наступного рівня відкривається.
- Вівтар = точка respawn (до активації мід-алтаря або апгрейду).

**Структура:**
```
[⛩ ALTAR / вхід] ← верх рівня, respawn точка
	   ↓ (спуск)
[Кімната 1: безпечна зона, 1–2 сек]
	   ↓
[Кімната 2: вороги + пастки]
	   ↓
[Кімната 3: іменна душа тут]
	   ↓
[Нижня частина рівня]
   ├──►  [🕳 вхід до бічного vertical] (праворуч — обов'язковий)
   └──◄  [🕳 вхід до void] (ліворуч — необов'язковий)
```
Кімнати стикуються вертикально. Ширина рівня: 320–480 px, висота: 1200–2000 px залежно від кола.

**Камера:** плавно слідує за гравцем вертикально; горизонтальна мертва зона ±60 px.

**Розміщення душ:**
- Іменна душа — в одній з нижніх кімнат, захищена ворогом або закрита платформою.
- Звичайна душа (якщо є) — в окремій ніші збоку, потрібен невеликий стрибковий маневр.

**Win condition:**
1. Підібрати іменну душу.
2. Пройти обов'язковий бічний vertical-рівень, якщо він є на цьому колі.
3. Повернутись до вівтаря з душею → доставити [E].

> **Void** — не є обов'язковою умовою переходу. Гравець може пропустити.

**Особливості за колами:**
- Кола 1–3: рівні короткі (3 кімнати), вороги мінімальні — вчимось механіці вівтаря.
- Кола 4–7: рівні довші (4–5 кімнат), підйом назад стає основним челенджем.
- Кола 8–10: максимальна висота + пастки на підйомі, апгрейд "Освячений Камінь" стає критичним.

**Душ:** 1 іменна + 0–1 звичайна.

---

#### `void` — Пустота

**Суть:** велика відкрита печера без чіткого напрямку. Нема єдиного шляху — гравець вільно досліджує простір. Вихід прихований або охороняється.

**Структура:**
```
Один великий відкритий простір: ~1600×1200 px (5×4 екрани).
Платформи розкидані нерегулярно. Нема стелі-підлоги як обмежень.
Вихід закритий поки не зібрані всі іменні душі рівня.
```

**Камера:** зум 0.8 (видно більше простору); вільне стеження з lookahead.

**Розміщення душ:**
- Іменна — в глибині печери, часто за природньою перешкодою (промінь вогню, вузький прохід).
- Звичайних 3–5 — розкидані рівномірно, частина видима відразу, частина схована під платформами або в нішах (доступно з `soul_sense`).
- Прихована душа з'являється тут частіше ніж в інших типах.

**Вороги:** патрулюють широкі зони, більша зона виявлення ніж на `vertical`. Кількість на 1 більше ніж стандарт кола.

**Ліміт смертей:** 5 (замість стандартних 3). Після 5-ї смерті — провал рівня, рестарт.

**Win condition:** зібрати іменну душу + всі помічені (підсвічені) звичайні → вихід відкривається.

**Особливості:**
- Немає обов'язку підбирати всі звичайні душі — але кожна дає Світло і +1 до лічильника доставлених.
- Апгрейд `tracker` особливо корисний — показує напрям до найближчої нерозбудженої.
- Апгрейд `map` на старті дає контур усієї печери на 3 сек — критично для орієнтування.

**Душ:** 1 іменна + 3–5 звичайних.

#### `boss` — Бос-арена

**Суть:** замкнена арена де гравець протистоїть охоронцеві душ. Вбити боса неможливо — перемога через виконання механіки арени. Вихід заблокований поки бос активний.

**Структура:**
```
Статична арена: ~800×600 px (2–3 екрани).
Геометрія підібрана під механіку конкретного боса.
Кілька платформ різної висоти. Нема пасток (арена сама є небезпекою).
```

**Камера:** фіксований зум щоб вся арена була видна одразу (або близько до цього). Без lookahead.

**Розміщення душ:**
- Іменних 1–2 — «звільняються» після перемоги або захищені механікою (бос стоїть між ними і гравцем).
- На колах де бос без назви (40, 60, 80, 90) — 1 іменна, пряме завдання: дістати її поки бос заважає.

**Механіки перемоги (залежать від боса):**
- Зібрати предмети/уламки й добігти до точки активації.
- Активувати тотеми в правильному порядку.
- Тримати молитву (hold) під час паузи боса.
- Оглушити посохом і пройти крізь арену.
- Впізнати справжнього серед копій.

**Стан STUNNED:** удар посохом оглушує на 6 сек. Більшість механік вимагають оглушення як умову для наступного кроку. Посох → оглушення → дія → повторити.

**Win condition:** механіко-специфічна (сигнал `win_condition_met` від BossAI). Після перемоги — вихід відкривається, іменні душі стають доступними для підбору.

**Особливості:**
- Бос-рівні завжди статичні (не процедурні).
- Смертей ліміту немає — можна гинути скільки завгодно.
- `faith_shield` (авто-блок 1/рівень) — єдиний рятівний апгрейд проти першого неочікуваного удару.

**Душ:** 1–2 іменних (після перемоги).

### Гібридна генерація

**Статичні (~35 рівнів):**
- Перший рівень кожного кола (1, 11, 21...91) — наративні
- Бос-рівні (10, 20, 30, 50, 70, 100)
- Всі 20 рівнів з прихованими душами
- Мілстоуни (50, 75, 99, 100)

**Процедурні (~65 рівнів):**
- Збираються з кімнат-блоків при завантаженні
- Seed = ID рівня → однаковий рівень завжди однаковий
- Структура: `вхід (безпечний) → 1–4 основні кімнати → вихід`
- 20–30 кімнат на коло в пулі

### Difficulty Zones (зони складності платформінгу)

Кожен вертикальний рівень отримує `difficulty_zone` — тир, що визначає відстань між платформами та їх тип.  
Розраховується з `LevelGenerator.get_zone(level_id)`.

| Тир | Відстань між рядами | Тип платформи | Ширина платформи |
|-----|---------------------|---------------|-----------------|
| `easy` | 100 px | `stone` (статична) | 220 px |
| `medium` | 150 px | `stone` (статична) | 110 px |
| `hard` | 200 px | `moving_horizontal` | 110 px |
| `extreme` | 200 px | `moving_vertical` | 110 px |

**Прогресія тирів всередині кола** (за позицією рівня 0–9):

| Позиції | Базовий тир |
|---------|-------------|
| 0–2 | `easy` |
| 3–5 | `medium` |
| 6–8 | `hard` |
| 9 | `extreme` |

Кола 4–7: базовий тир +1 (easy → medium тощо).  
Кола 8–10: базовий тир +2.

**Валідація шляху:** перед фіналізацією процедурного рівня BFS-алгоритм перевіряє, що гравець може дістатись знизу вгору. Якщо проміжок між платформами перевищує MAX\_JUMP\_HEIGHT (200 px), автоматично вставляється bridge-платформа.  
Для `moving_vertical` платформ ефективний радіус досягнення враховує відстань руху (MOVING\_V\_DISTANCE = 80 px) — тобто реальний launch\_y вираховується від верхньої точки траєкторії.

**Safe Area:** підлога та стеля вертикальних кімнат враховують OS-інсети нотчу / home bar через `DisplayServer.get_display_safe_area()`. Контент ніколи не потрапляє під системний UI.

**Мінімальна висота вертикального рівня:** 3840 px (2 екрани × 1920 px).

Зверху арени — горизонтальний індикатор з ціллю боса. **Не HP** — це
прогрес-метр (боси беззпрограшні, метр заповнюється по виконанню

Вміст залежить від боса:

| Бос | Заголовок | Формат |
|-----|-----------|--------|

| boss_03 | Кристали | "X / 3" (int) |

## 11. Система смерті та Respawn

**Конфіг:** `death_system_config.json`

### Послідовність смерті
1. Анімація смерті
2. Екран темніє
3. Гріх +5%
4. Якщо нес душу — вона падає на місці смерті (чекає наступного забігу)
5. Лічильник смертей +1
6. Перевірка ліміту
7. Respawn: гравець телепортується на точку respawn, всі вороги вертаються до своїх початкових позицій (патруль)

### Ліміти по типах рівнів

| Тип рівня | Ліміт | Поведінка при перевищенні |
|-----------|-------|--------------------------|
| `vertical` | 3 | М'який — +1 extra life, +5% гріху |
| `void` | 5 | М'який (більше бо рівні довші) |
| `boss` | необмежено | — |

**М'який ліміт** — гравець не вилітає з рівня. Отримує ще одне життя але платить гріхом.

### Точки respawn

| Тип рівня | Точка respawn |
|-----------|--------------|
| `vertical` | Верхній вівтар (за замовчуванням) |
| `vertical` + апгрейд | Останній активований мід-алтар (якщо є) |
| `void` | Початок рівня |
| `boss` | Вхід у бос-арену |

> Після активації мід-алтаря ([E]) — respawn прив'язується до нього до кінця рівня. Після смерті та respawn-у мід-алтар залишається активною точкою (не скидається).

## 12. Збереження

**Конфіг та скрипт:** `scripts/SaveManager.gd`

- 3 слоти збереження (`user://saves/slot_1.json` і т.д.)
- Перед кожним записом — backup копія (`slot_1_backup.json`)
- При пошкодженому файлі — автоматичне відновлення з backup
- Зберігається після кожного рівня (при появі екрану level complete)
- Cloud stub — заглушка для майбутньої синхронізації (`CLOUD_ENABLED = false`)

### Що зберігається
- Поточний рівень та коло
- Зібрані душі та приховані душі
- Куплені апгрейди та баланс Світла
- Поточний гріх
- Налаштування (звук, мова, графіка, **переназначені клавіші**, **haptics toggle**)
- Прапорець `no_ads_purchased`
- Переглянуті підказки туторіалу
- **Per-level personal bests** — `level_bests` Dictionary (`{ time, stars,
  souls, deaths }` per level_id). Оновлюється тільки при покращенні
  (більше зірок, або те ж число зірок + кращий час).
- **Statistics** — `statistics` bucket: `total_play_seconds`,
  `levels_cleared`, `deaths_total`, `deaths_by_cause: { fall: N, … }`,
  `light_earned_total`, `light_spent_total`. Інкрементується GameManager'ом
  у точках смерті/завершення/spend_light.
- **Mobile button layout** — `mobile_layout: { size_scale: float,
  offsets: { action: {x, y} } }`. Auto-flush при save щоб crash mid-game
  не втрачав drag-tweak'и.

### Пауза
**Конфіг:** `pause_screen_config.json`  
Trigger: кнопка пауза або Escape. Blur overlay.

Кнопки: Продовжити / Врятовані Душі / **📊 Статистика** / Налаштування /
Головне меню. При виборі "Головне меню" — підтвердження з попередженням що
душа в руках буде втрачена.

### Statistics screen
**Скрипт:** `scripts/ui/StatisticsScreen.gd`  
**Сцена:** `scenes/ui/StatisticsScreen.tscn`

Окрема overlay-CanvasLayer, відкривається з PauseScreen → "📊 Статистика".
Секції:
- **⏱ Прогрес** — загальний час гри (HH:MM:SS), поточний рівень,
  завершено рівнів
- **👻 Душі** — звичайних X/100, прихованих X/20
- **💀 Смерті** — загалом + per-cause breakdown ("від падіння", "від ворога",
  "у лаві", "на шипах", …)
- **💡 Світло** — поточний баланс, зароблено за все, витрачено за все
- **🏆 Рекорди** — найкращий клір серед усіх рівнів (id + час + ★)
- **😈 Гріх** — поточний %

Дані беруться з `SaveManager.data["statistics"]` що оновлюється `GameManager`
у `trigger_death(cause)`, `complete_level()`, та `SaveManager.spend_light()`.

### Level Complete
**Конфіг:** `level_complete_config.json`

**Рубрика зірок** (per-level personal-best система):
- ★★★ — clear + **0 смертей** + час ≤ `target_time`
- ★★☆ — clear + 0 смертей (час перевищено)
- ★☆☆ — інакше (включно з 1+ смертю)

`target_time` бере з `levels_config.target_time_seconds` або fallback
`45 + circle * 6` секунд.

Показує: душі / смерті / **час забігу** / **попередній рекорд** (час + ★)
/ приріст гріху / зароблене Світло / портрети знайдених душ.

Якщо поточний run покращив запис → badge **"✨ НОВИЙ РЕКОРД ✨"** під
рядом з зірками.

Кнопки: Хаб Раю / Наступний рівень.

**Зберігання:** `SaveManager.update_level_best(id, time, stars, souls,
deaths)` — записує лише якщо stars зросли або при тих же stars time менший.

### Колекція душ
**Конфіг:** `collection_screen_config.json`

Сітка 8 колонок. Стани:
- Збережена звичайна: срібна рамка
- Збережена прихована: золота рамка + ✦
- Не знайдена звичайна: темна + ?
- Не знайдена прихована: золота рамка + ? (видима завжди)

Лічильник ✦ завжди видимий. Доступна з головного меню та паузи.

При 100/100: теплий блиск + тихий дзвін + маленький текстовий попап.

**Per-circle progress strip** під заголовком — 10 клітин (К1..К10):
- "К%d" + "X/Y" звичайних душ
- "✦ X/Y" прихованих душ — лише якщо в колі є приховані
- Завершені цілком (X==Y) — золотий tint
- Допомагає зорієнтуватись "які кола ще не зачищені"

### Хаб Раю
**Конфіг:** `hub_config.json`

З'являється перед кожним рівнем (можна пропустити). Показує повідомлення Бога, стан гравця, кнопку старту. Пролог (рівень 1) — не можна пропустити.

**Continue button** показує:
- "Далі →"
- "Коло X • Рівень Y"
- "🏆 0:23 ★★★" — лише якщо рівень уже пройдений (з SaveManager.get_level_best)

### Головне меню
Кнопки: Грати / Збережені Душі / Налаштування / Без реклами / Підтримати / Вийти.

Слоти збереження: показують поточне коло, рівень, кількість душ, час гри.

### Налаштування
**Конфіг:** `settings_config.json`

4 вкладки:
- **🔊 Звук:** Master / Music / SFX слайдери (0–100), Вимкнути все,
  **Вібрація (mobile)** toggle (HapticManager).
- **🌐 Мова:** Українська / English (застосовується миттєво)
- **🖥 Графіка:** Повноекранний, Роздільна здатність (якщо не fullscreen),
  Якість Low/Medium/High, V-Sync, FHD/HD preset toggle
- **⌨ Клавіші:**
  - **📱 Мобільні кнопки** (зверху таба): slider розміру 60-140%,
    "✋ Редагувати позиції кнопок" → drag-mode overlay, "↺ Скинути позиції".
  - Перепризначення 7 keyboard actions (`move_left`, `move_right`,

	"Натисніть клавішу..." → наступний key стає biding'ом. **Esc** скасовує.
	Кнопка "↺ Скинути всі" повертає до snapshot з project.godot.
	Зберігається у `keybindings: { action: physical_keycode }` дикті.
	Non-key events (gamepad/mouse) на тих же діях не зачіпаються.

Зберігається в `user://settings.json` при кожній зміні.

## 18. Довідник конфігів

Усі конфіги лежать в корені проекту. Змінюй значення тут — код підхоплює автоматично.

---

### `levels_config.json`
Всі 118 рівнів (100 основних + 18 бічних). Для кожного рівня:
- `id` — унікальний ID. Основні: 1–100. Бічні: 103–189 (= `parent_id + 100`).
- `circle` — номер кола (1–10)
- `name` — назва рівня
- `type` — тип: `vertical` / `void` / `boss`
- `difficulty` — базова складність
- `enemies` — які вороги присутні
- `traps` — які пастки
- `bonuses` — які бонуси можна підібрати
- `soul_types` — типи душ (innocent / sleeping / mimic)
- `special_mechanics` — особливі механіки (wind_push, darkness тощо)
- `is_narrative` — `true` для наративних рівнів (перший рівень кожного кола)

**Поля бічних рівнів:**
- `has_branch: true` — на основному рівні є вхід до бічного
- `branch_direction: "left" | "right"` — void = ліворуч, решта = праворуч
- `branch_of: <parent_id>` — на бічному рівні: ID батьківського vertical
- `branch_required: true | false` — чи є проходження бічного обов'язковим

---

### `level_generation_config.json`
- `static_levels` — які рівні статичні (не генеруються)
- `room_pools` — пули кімнат для кожного кола
- `difficulty_injection` — модифікатори складності в межах кола
- `level_type_distribution` — шаблон розподілу типів рівнів в колі

---

### `souls_collection.json`
- Всі 100 іменних душ: ім'я, вік, коло, рівень, тип, гріх
- 20 прихованих душ: ім'я, підказка, нагорода

---

### `soul_mechanics_config.json`
- `soul_types` — параметри кожного типу (innocent / sleeping / mimic)
- `sleeping.minigame_pool_by_circles` — які міні-ігри доступні в яких колах
- `sleeping.minigames` — параметри кожної міні-гри (тривалість, умова провалу)
- `mimic.exorcism` — тривалість утримання, нагорода, штраф
- `carrying_mechanic` — поведінка при смерті з душею
- `enemy_chase.scaling_by_circle` — час погоні, швидкість, макс. переслідувачів

---

### `enemies_config.json`
Для кожного ворога:
- `move_speed` — швидкість патрулю
- `detection_range` — радіус виявлення гравця
- `patrol_distance` — довжина маршруту патрулю
- `alert_duration` — тривалість фази ALERT
- `special` — особлива здібність (knockback_resistance, sin_aura тощо)

---

### `enemy_sprite_map.json`
- `base_path` — базовий шлях `res://Assets/enemies/`
- Для кожного ворога: `pack`, `character`, `animations` (маппінг назв анімацій)

---

### `bosses_config.json`
Для кожного боса:
- `stats` — швидкість, дальність виявлення
- `mechanic` — тип і опис механіки, умова перемоги
- `arena` — розміри та платформи арени
- `phases` — для Люцифера: умови переходу між фазами

---

### `platforms_config.json`
Для кожного типу платформи:
- `behavior` — поведінка (solid_always, breaks_after_standing тощо)
- Специфічні параметри: `delay_before_break`, `friction`, `sin_per_second`, `sin_threshold` тощо
- `circles` — в яких колах з'являється
- `sound_loop`, `sound_break` — звуки

---

### `placeholder_assets_config.json`
- `color` — колір прямокутника для кожного типу об'єкта
- `size` — розмір [width, height]
- `opacity` — прозорість (для напівпрозорих платформ)
- `label` — текст підпису

---

### `upgrades_config.json`
- `currency` — скільки Світла дає кожна дія
- Для кожного апгрейду: `cost`, `max_level`, `effect` (тип і значення)

---

### `camera_config.json`
- `lookahead_distance` — на скільки камера дивиться вперед (120 px)
- `direction_change_delay` — затримка при розвороті (0.3 сек)
- `vertical_deadzone` — мертва зона по вертикалі
- `void_level_zoom` — зум на void рівнях (0.8)

---

### `hud_config.json`
- `sin_bar.colors` — кольори шкали гріху по порогах
- `level_info.fade_after` — через скільки сек зникає назва рівня (3 сек)
- `bonus_slots.expiring_threshold` — за скільки сек до кінця бонус блимає (3 сек)

---

### `hub_config.json`
- `god_messages` — повідомлення по рівнях і подіях
- `prologue_scenes` — сцени вступного діалогу
- `message_styles` — стилі повідомлень (calm / warning / personal тощо)

---

### `death_system_config.json`
- `limits` — ліміти смертей по типах рівнів
- `soft_limit_sin_penalty` — скільки гріху за перевищення (5%)
- `respawn_points` — де respawn по типах рівнів

---

### `settings_config.json`
- `tabs` — вкладки налаштувань (sound / language / graphics)
- Для кожного контролу: `type`, `default`, `min/max` (для слайдерів)
- `save.path` — куди зберігати (`user://settings.json`)

---

### `audio_config.json`
- `music.tracks` — треки для кожного кола та особливих моментів
- `music.system.crossfade_duration` — тривалість переходу між треками
- `sfx` — шляхи до всіх звукових ефектів по категоріях
- `spatial_audio` — дальність просторових звуків

---

### `collection_screen_config.json`
- `grid.columns` — кількість колонок сітки (8)
- `cell_states` — візуальні стани клітинок

### `level_complete_config.json`
- `stars.rules` — умови для 1/2/3 зірок
- `stats.items` — які статистики показувати
- `sounds` — звуки для кожної зірки

---

### `pause_screen_config.json`

- `exit_confirmation` — тексти підтвердження виходу

---

### `tutorial_config.json`
- `settings.hint_display_duration` — скільки секунд показується підказка (4 сек)
- `settings.exceptions.minigame_hint` — підказка міні-гри завжди (1.5 сек)
- `triggers` — умови появи кожної підказки (рівень, тригер, відстань)
- `visual_demos.per_trigger` — тип демонстрації для кожної підказки

### `monetization_config.json`
- `admob.banner.unit_id_release` — **сюди вставляєш свій AdMob Banner ID**
- `admob.interstitial.unit_id_release` — **сюди вставляєш свій Interstitial ID**
- `admob.interstitial.cooldown_seconds` — мінімальний інтервал між рекламою (120 сек)
- `admob.interstitial.show_on` — коли показувати повноекранну рекламу
- `admob.banner.enabled` / `admob.interstitial.enabled` — вмикання/вимикання
- `iap.no_ads.sku` — SKU для покупки "Без реклами" в Google Play Console
- `iap.donate.tiers` — список SKU для донатів
- `layout.banner_height_px` — висота банера в пікселях (60)

### `localization/uk.json` та `localization/en.json`
Всі тексти гри згруповані за простором імен.
